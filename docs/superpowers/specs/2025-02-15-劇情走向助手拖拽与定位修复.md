# 劇情走向助手拖拽与定位修复设计

**日期**: 2025-02-15  
**状态**: 待审核  
**受影响组件**: [`src/劇情走向助手/FloatingPanel.vue`](../../src/劇情走向助手/FloatingPanel.vue)

## 问题背景

用户报告劇情走向助手浮动面板存在两个体验问题：

1. **浮动按钮无法正常拖动**：按下鼠标后立即移动时，按钮不会跟随鼠标拖拽，必须按住不动 420ms 才能拖动。
2. **展开面板跑出屏幕外**：点击按钮打开面板后，面板有时会定位在整个浏览器视口之外或 SillyTavern
   chat 区域之外，用户无法看到面板内容。

## 根因分析

### 问题 1：鼠标拖拽失效

当前实现将鼠标和触摸事件混用同一套长按状态机：

- [`onDown()`](../../src/劇情走向助手/FloatingPanel.vue:374) 在鼠标按下时只设置 420ms 定时器
- [`onMove()`](../../src/劇情走向助手/FloatingPanel.vue:391) 检测到鼠标移动超过 12px 时会取消定时器并设置
  `pressCancelled = true`
- 因此普通鼠标拖拽（按下后立即移动）会在定时器触发前被取消，无法进入拖拽状态

这套逻辑是为触摸设备设计的，用于区分点击和长按拖拽，避免误触。但鼠标不需要这个限制——桌面端用户期望按下即可拖动。

### 问题 2：面板定位超出 chat 区域

当前 [`panelStyle`](../../src/劇情走向助手/FloatingPanel.vue:323) 和
[`clampToViewport()`](../../src/劇情走向助手/FloatingPanel.vue:301) 都基于 `window.visualViewport`
或整个浏览器窗口计算边界，没有识别 SillyTavern 的 chat 容器（`#chat`）。由于：

- 按钮通过 `v-if="isVisible && !isExpanded"` 在面板打开时消失
- 面板通过 `v-if="isExpanded"` 独立渲染，不依赖按钮 DOM 位置
- 面板位置计算依赖已消失的 `tabLeft`，且只考虑 viewport 边界

因此面板可能出现在 chat 区域之外（如被侧边栏或其他 UI 遮挡），或在移动端因软键盘弹起导致计算错误。

## 设计方案

### 1. Chat 区域边界检测

新增 [`chatBounds()`](../../src/劇情走向助手/FloatingPanel.vue:265) 函数，优先查找 SillyTavern 的 `#chat` 容器并使用其
`getBoundingClientRect()` 获取实际可视区域：

```typescript
function chatBounds() {
  const chat = document.querySelector('#chat');
  if (chat) {
    const rect = chat.getBoundingClientRect();
    // 有效性检查：宽高都大于 0
    if (rect.width > 0 && rect.height > 0) {
      return {
        left: rect.left,
        top: rect.top,
        width: rect.width,
        height: rect.height,
      };
    }
  }
  // 回退到 visualViewport
  return viewportBounds();
}
```

**边界有效性判断**：只有当 `rect.width > 0 && rect.height > 0` 才使用 chat 容器边界，否则回退到
`viewportBounds()`，确保在容器不存在或隐藏时不会崩溃。

### 2. 按钮定位与边界限制

修改 [`clampToViewport()`](../../src/劇情走向助手/FloatingPanel.vue:301) 改为使用 `chatBounds()` 替代
`viewportBounds()`，确保按钮始终停留在 chat 区域内：

```typescript
function clampToViewport() {
  const { left, top, width, height } = chatBounds();
  const minX = left + VIEWPORT_INSET;
  const minY = top + VIEWPORT_INSET;
  const maxX = Math.max(minX, left + width - TAB_W - VIEWPORT_INSET);
  const maxY = Math.max(minY, top + height - TAB_H - VIEWPORT_INSET);
  if (pos.dock === 'right') pos.x = maxX;
  else if (pos.dock === 'left') pos.x = minX;
  pos.x = Math.min(Math.max(minX, pos.x), maxX);
  pos.y = Math.min(Math.max(minY, pos.y), maxY);
}
```

同时修改 [`finishPointer()`](../../src/劇情走向助手/FloatingPanel.vue:413) 和
[`onTouchEnd()`](../../src/劇情走向助手/FloatingPanel.vue:505) 中的边缘吸附计算，使用 `chatBounds()` 替代
`viewportBounds()`。

### 3. 鼠标立即拖拽

修改 [`onDown()`](../../src/劇情走向助手/FloatingPanel.vue:374)：

- **鼠标路径**（`pointerType === 'mouse'`）：立即设置 `dragging.value = true` 并调用
  `e.currentTarget.setPointerCapture(e.pointerId)`，不再设置长按定时器
- **触摸路径**保持不变：仍通过 420ms 定时器实现长按拖拽，避免破坏移动端点击和页面滚动体验

修改 [`onMove()`](../../src/劇情走向助手/FloatingPanel.vue:391)：

- 移除鼠标路径的 `PRESS_SLOP` 检查和 `pressCancelled` 逻辑
- 鼠标移动时直接更新 `pos.x` 和 `pos.y`
- 触摸路径保持不变

修改 [`finishPointer()`](../../src/劇情走向助手/FloatingPanel.vue:413)：

- 鼠标拖拽结束时调用 `e.currentTarget.releasePointerCapture(e.pointerId)`
- 通过 `wasDragging` 判断是拖拽还是点击：
  - 拖拽：保存位置，边缘吸附，抑制点击
  - 点击：调用 `toggleExpanded()`，抑制点击（避免拖拽结束时误触发）

**点击抑制机制**：保留现有的 `suppressClickForCurrentGesture()` 和
`clickSuppressionTimer`，确保拖拽结束后 500ms 内不会触发点击事件，防止用户在拖拽结束时误打开面板。

### 4. 展开面板定位

重写 [`panelStyle`](../../src/劇情走向助手/FloatingPanel.vue:323)：

- 使用 `chatBounds()` 获取 chat 区域边界
- **窄屏模式**（`width < 440`）：面板铺满 chat 区域宽度，顶部对齐
- **宽屏模式**：
  - 面板宽度 `min(360px, chatWidth - VIEWPORT_INSET * 2)`
  - 面板高度 `min(80% chatHeight, chatHeight - VIEWPORT_INSET * 2)`
  - 优先放在 chat 区域中央或右侧（不再依赖已隐藏的按钮位置）
  - 确保面板 `left` 和 `top` 在 chat 区域内，`left + width` 和 `top + height` 不超出边界

**移除临时诊断日志**：删除此前在 `panelStyle` 和 `onMove` 中加入的 `console.warn` 诊断日志。

### 5. Pointer Capture

使用 [`setPointerCapture()`](https://developer.mozilla.org/en-US/docs/Web/API/Element/setPointerCapture) 和
`releasePointerCapture()` 确保鼠标移出按钮后仍能持续收到拖拽事件，避免拖拽到按钮边缘时中断。

## 测试验证

### 构建验证

```powershell
pnpm build
```

预期：webpack 编译成功，无错误。

### 功能验证

1. **鼠标拖拽**：
   - 在桌面浏览器中，按下浮动按钮后立即移动鼠标
   - 预期：按钮跟随鼠标实时拖动，无需等待
   - 拖拽到边缘时：按钮应自动吸附到 chat 区域左侧或右侧

2. **鼠标点击**：
   - 按下浮动按钮后不移动，直接释放
   - 预期：面板打开，按钮消失

3. **触摸拖拽**（移动设备或触摸屏）：
   - 按住浮动按钮 420ms 后移动
   - 预期：按钮跟随手指拖动
   - 轻触后立即释放：面板打开（不进入拖拽）

4. **面板定位**：
   - 在不同位置打开面板
   - 预期：面板始终完整显示在 chat 区域内，不被遮挡
   - 窄屏（如手机）：面板铺满宽度
   - 宽屏：面板在 chat 区域中央或右侧

5. **响应式**：
   - 调整浏览器窗口大小
   - 打开浏览器开发者工具（改变 chat 区域大小）
   - 预期：按钮和面板自动重新计算位置，保持在 chat 区域内
