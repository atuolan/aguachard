# 劇情走向助手副 API 設計

## 目標

在劇情走向助手中增加可選的副 API 配置，使劇情走向生成可以不依賴酒館當前主 API。功能需要支持多組 API
Key、指定模型、從當前酒館讀取配置、拉取模型、測試連線，以及跨設備導出與導入。

## 已確認的使用方式

- 副 API 配置直接放在劇情走向助手腳本的 `data` 中。
- 不以 `localStorage` 或 IndexedDB 作為主保存位置，因為它們不能隨腳本跨設備同步。
- API Key 按需求以明文保存到腳本 `data`，因此導出包含資料的腳本時可能會一併暴露 Key。
- 支持保存多個 API 方案，並保存目前選中的方案。
- 可讀取當前酒館主 API 的地址、Key、來源和模型，另存為一個副 API 方案。
- 未選擇副 API 方案時，劇情生成維持使用酒館當前主 API。
- 已選擇副 API 方案時，劇情生成使用該方案的 `custom_api`。
- 「測試連線」固定發送一次短測試提示詞，因此明確會消耗一次模型額度，並在面板內顯示模型回覆。

## 資料模型

腳本變量使用 `getVariables({ type: 'script' })` 與 `replaceVariables(..., { type: 'script' })`
讀寫。建議使用單一命名空間 `storyDirectionApi`，避免污染其他腳本變量。

```ts
interface ApiStore {
  version: 1;
  activeId: string;
  schemes: ApiScheme[];
}

interface ApiScheme {
  id: string;
  name: string;
  source: string;
  apiurl: string;
  key: string;
  model: string;
  proxy_preset?: string;
  createdAt: number;
  updatedAt: number;
}
```

資料讀取時必須做容錯與正規化：無效資料被忽略，缺失的頂層欄位使用空的預設值，`activeId`
若不再對應任何方案則清空。保存時保留未知頂層欄位不是必要要求，但不得影響其他腳本變量。

## 介面設計

在現有浮動面板中增加可折疊的「API 設定」區，原有五個劇情選項與提示詞編輯器保持不變。

### 方案操作

- 方案選擇下拉框顯示所有已保存方案，另提供「使用主 API」選項。
- 「新增方案」清空編輯欄位並生成新的方案 ID。
- 「保存方案」在有 ID 時覆蓋目前編輯方案，沒有 ID 時建立新方案。
- 「刪除方案」刪除目前編輯方案；若刪除 active 方案，切回主 API。
- 切換方案立即保存 `activeId`。

### 編輯欄位

- 方案名稱
- API Base URL
- API Key
- API Source，預設為 `openai`
- 模型名稱，支持自由輸入
- 可選的代理預設名稱欄位，為 `proxy_preset` 預留兼容性

Key 輸入使用密碼欄位，提供顯示/隱藏切換。由於使用者已確認需要跨設備保存，保存時不遮蔽或丟棄 Key。

### 操作按鈕

按鈕按以下職責分離：

- 「從當前酒館讀取」：讀取主 API 配置，填入編輯表單並建立或準備保存一個新方案；不切換酒館主 API。
- 「拉取模型」：使用目前表單的 `apiurl` 與 `key` 呼叫 `getModelList()`，把結果填入模型選擇器；模型欄位仍可手動輸入。
- 「測試連線」：使用目前表單內容呼叫一次
  `generateRaw()`，發送固定短提示詞，明確消耗一次額度；將回覆、耗時和錯誤狀態顯示在按鈕下方。
- 「保存方案」：將目前表單內容寫回腳本 `data`。

所有異步操作期間停用相關按鈕，避免重複請求。錯誤只顯示在面板內並記錄到 console，不使用阻塞式瀏覽器彈窗。

## API 請求流程

### 模型列表

使用酒館助手提供的
`getModelList({ apiurl, key })`。成功後將返回的模型名稱去重並排序，保留當前手動輸入但不在列表中的模型。若接口不支持模型列表，顯示錯誤並保留手動輸入能力。

`proxy_preset` 方案若沒有可直接使用的
`apiurl`，本輪不強行自行請求模型列表；應提示先補充可用地址，或通過酒館代理預設生成測試。

### 測試連線

測試前檢查 `model` 必填；若使用直接地址模式，`apiurl` 與 `key` 按接口需要校驗。使用以下類型的配置調用 `generateRaw()`：

```ts
await generateRaw({
  user_input: '請只回覆：連線測試成功',
  should_silence: true,
  should_stream: false,
  max_chat_history: 0,
  custom_api: {
    apiurl,
    key,
    model,
    source,
    ...(proxy_preset ? { proxy_preset } : {}),
  },
});
```

測試不得寫入聊天記錄，不得切換酒館主 API，也不得修改
`activeId`。成功時顯示模型返回內容；失敗時顯示可讀錯誤。由於請求本身會消耗額度，按鈕附近必須保留明確的消耗提示。

### 正式生成

現有五分叉提示詞與解析流程不改動。生成時：

- `activeId` 對應有效方案：把方案轉成 `custom_api` 傳給 `generateRaw()`。
- `activeId` 為空或方案不存在：不傳 `custom_api`，維持目前主 API 行為。
- API Key 不寫入 console、錯誤訊息或生成結果之外的 UI 文本。

## 讀取當前酒館主 API

優先使用 SillyTavern/酒館助手已暴露的當前 Chat Completion 配置。讀取結果映射到：

- API 地址 -> `apiurl`
- API Key -> `key`
- API 来源 -> `source`
- 当前模型 -> `model`

若酒館版本或安全策略只暴露遮罩後的 Key、沒有暴露 Key 或接口結構不同，保留能讀到的欄位，並提示使用者手動補填 Key。該操作不能通過猜測 DOM 內容或讀取不穩定的內部欄位來偽造完整配置。

## 錯誤與狀態

需要至少區分以下狀態：

- 空配置：缺少必要字段，阻止請求並指出缺少項目。
- 拉取中：模型列表請求進行中。
- 測試中：一次性生成請求進行中，顯示消耗額度提示。
- 保存成功：顯示方案名稱和保存結果。
- 請求失敗：顯示 API 返回錯誤或網絡錯誤，保留表單內容。
- 回覆成功：顯示回覆內容與耗時。

## 安全與導出說明

Key 明文存在腳本
`data`，只要腳本資料被導出，Key 就可能被一併導出。介面與文檔必須明確提示：不要把包含副 API 配置的腳本分享給不可信任的人。SillyTavern 的腳本資料導出開關仍由其腳本導出設定控制；本功能不另建資料夾，也不依賴設備本地資料庫。

## 測試策略

- 單元級：測試資料正規化、方案新增/覆蓋/刪除、activeId 回退和 `custom_api` 映射。
- 整合級：通過 TypeScript/webpack 構建確認 Vue 模板與酒館助手接口類型可編譯。
- 手動級：
  - 新增多個方案並切換，刷新腳本後確認仍存在。
  - 導出並在另一設備導入腳本，確認方案與 Key 隨 `data` 存在。
  - 從當前主 API 讀取配置並保存。
  - 拉取模型並選擇指定模型。
  - 點擊「測試連線」，確認收到模型回覆且知道該操作消耗額度。
  - 選中副 API 生成五個候選，確認未改動主 API。
  - 切回主 API，確認生成恢復原行為。
  - 校驗錯誤、空配置與 API 不支持模型列表時的界面狀態。
